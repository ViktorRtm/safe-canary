# Incident runbook — неудачный canary ML-модели

**Сценарий.** Stable v1 (95%) и canary v2 (5%) работают параллельно. Одна из проверок качества или технических метрик требует остановки выпуска.

## Условия остановки (демонстрационные значения)

- HTTP error rate > 1% на наблюдаемом окне.
- Общая p95 latency > 250 мс в тестовом окружении.
- Recall или F1 у canary ниже стабильной версии более чем на 0,05 абсолютного значения.
- Readiness canary не проходит, контракт входных данных изменён или модель не загружается.
- Нет достоверных метрик, недостаточная выборка или ещё не пришёл ground truth: **не продвигать**.

## Порядок действий дежурного инженера

1. **Зафиксировать событие:** время, release ID, Git SHA / image digest, model versions, долю трафика, конфигурацию, результаты gate, графики и логи request_id.
2. **Остановить promotion:** не увеличивать вес canary и не пересобирать образ.
3. **Вернуть трафик на v1:** `python scripts/route.py 0` (атомарное изменение файла + `nginx -t` + graceful reload).
4. **Проверить доступность:** `python scripts/smoke.py`; отдельно убедиться, что новых v2 predictions больше нет.
5. **Сохранить доказательства:** `reports/canary_assessment.json` и `reports/rollback_proof.json`, результаты технического и ML-мониторинга.
6. **Рассчитать влияние:** затронутые запросы, HTTP-ошибки и задержки, долю canary, наличие потерь, число неверных предсказаний по доступному ground truth.
7. **Оповестить ответственных:** дежурного инженера, ML engineer, владельца сервиса и бизнес-владельца при существенном влиянии.
8. **Разобрать причину:** ошибка модели, contract drift, latency, отсутствие данных или конфигурация proxy; создать задачу на исправление.
9. **Повторный выпуск:** только новый проверенный релиз и новый canary с подтверждённым baseline; не повторять rollout автоматически при невыясненной причине.

## Важные ограничения

Этот стенд stateless, поэтому проверяется сохранение успешности наблюдаемых HTTP-запросов при переключении весов, а не абсолютная гарантия exactly-once delivery. В реальном сервисе для гарантированной доставки потребуются клиентские retry с idempotency key, очереди/журналирование и контроль побочных эффектов. Canary по метрикам с задержанным ground truth нельзя автоматически продвигать до 100% по результатам только HTTP-тестов.
